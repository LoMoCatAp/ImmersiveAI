## 概述

本功能提供一款面向手机和平板的多模型 AI 对话应用。用户可安全配置多个模型供应商，在会话中选择模型并进行流式文本对话，同时获得遵循官方能力和参考工程的沉浸光感界面体验。

首版严格采用参考工程所示、适用于 HarmonyOS 6.1 / API 23 的官方 UI Design Kit 沉浸光感能力，聚焦导航和底部页签，并在设备不支持时提供可用且清晰的视觉降级。模型协议保持六类供应商入口，并归并为 OpenAI、Claude、Gemini 三种协议风格；仅参考 HiveChat 的协议分层、消息映射和流解析行为，针对 ArkTS 独立实现，不直接复制其源码。不得虚构沉浸光感 API、参数、模型供应商协议或模型能力。

## 用户场景与测试

### 用户故事 1：配置模型供应商（优先级：P1）

用户可通过应用内粘贴或 JSON 文件导入供应商配置，为 OpenAI 兼容接口、OpenAI、Anthropic、Google Gemini、DeepSeek 和 GLM 保存服务信息及 Key，并能验证、编辑、启用或删除配置。

**优先级原因**：有效且安全的供应商配置是所有 AI 对话能力的前置条件。

**独立测试**：在无既有配置的设备上导入或手动创建一项配置，确认敏感字段受到保护，且无效配置不会被用于对话。

**验收场景**：

1. **给定**用户尚未配置供应商，**当**用户填写必要信息并保存，**那么**应用应校验必填项并建立可选择的供应商配置。
2. **给定**用户持有符合约定结构的 JSON 文件，**当**用户选择并确认导入，**那么**应用应展示导入预览，取得确认后保存配置，并且不明文回显完整 Key。
3. **给定**导入文件格式错误、字段缺失或供应商类型不受支持，**当**应用解析文件，**那么**应用应拒绝导入并明确指出可修正的问题。
4. **给定**配置已保存，**当**用户编辑、停用或删除配置，**那么**变更应立即反映在可选模型列表中，删除前需要确认。

---

### 用户故事 2：进行流式 AI 对话（优先级：P1）

用户可选择已配置的供应商及模型，发送文本消息，实时查看流式响应，并执行停止生成、重新生成和复制回答等操作。

**优先级原因**：对话是应用的核心用户价值，与配置能力共同构成最小可用产品。

**独立测试**：使用一项有效配置新建会话、发送问题并观察完整流式响应，然后分别验证停止、重试和复制操作。

**验收场景**：

1. **给定**存在有效配置且网络可用，**当**用户选择模型并发送非空文本，**那么**用户消息应立即出现，回答应随服务返回逐步展示。
2. **给定**回答正在生成，**当**用户点击停止，**那么**应用应停止接收后续内容，并保留已收到的回答。
3. **给定**一条回答已完成或失败，**当**用户执行重新生成，**那么**应用应基于同一会话上下文重新请求，并明确区分新旧结果。
4. **给定**服务返回鉴权、限流、网络或协议错误，**当**请求失败，**那么**应用应展示可理解且不泄露 Key 的错误信息，并允许重试或切换配置。
5. **给定**所选模型没有可验证的文本对话能力，**当**用户尝试发起请求，**那么**应用不得臆测其能力或请求格式，而应阻止请求并提示检查配置。
6. **给定**服务实际返回独立推理字段或完整的推理标签片段，**当**应用解析流式响应，**那么**推理内容应进入可折叠分区，最终回答保持独立；应用不得生成、补写或猜测缺失的推理内容。

---

### 用户故事 3：管理本地会话历史（优先级：P2）

用户可在设备本地查看、新建、继续、重命名和删除会话，并在重新启动应用后恢复历史。

**优先级原因**：会话持久化显著提升连续使用体验，但不阻塞单次对话的核心价值。

**独立测试**：创建含多轮消息的会话，重启应用后继续对话，再验证重命名和删除。

**验收场景**：

1. **给定**用户完成一轮对话，**当**用户退出并重新打开应用，**那么**会话标题、模型标识、消息与时间信息应恢复。
2. **给定**存在多个历史会话，**当**用户选择其中一个，**那么**应用应展示正确的消息顺序并允许继续对话。
3. **给定**用户删除会话，**当**用户确认删除，**那么**该会话及其本地消息应被移除，其他会话不受影响。
4. **给定**历史记录为空或读取异常，**当**用户进入历史页，**那么**应用应显示明确空状态或恢复提示，而非空白页面。

---

### 用户故事 4：阅读格式化回答（优先级：P2）

用户可阅读包含标题、段落、列表、引用和代码块的 Markdown 回答，并复制所需文本。

**优先级原因**：结构化展示提高复杂回答的可读性。

**独立测试**：让模型返回覆盖首版支持语法的内容，验证结构、换行、长文本、代码块及复制行为。

**验收场景**：

1. **给定**回答含首版支持的 Markdown，**当**内容逐步到达并最终完成，**那么**应用应稳定展示相应结构且不显示原始控制标记。
2. **给定**回答含超长行或代码块，**当**用户阅读内容，**那么**内容应保持可访问、可滚动且不破坏页面布局。
3. **给定**回答含不受支持或格式不完整的标记，**当**应用渲染，**那么**应以安全的可读文本降级，不执行其中内容。

---

### 用户故事 5：体验官方沉浸光感与主题适配（优先级：P2）

用户在导航、底部页签和关键页面流转中获得与参考工程一致方向的官方沉浸光感体验；切换系统深浅色后，内容仍清晰可读。设备不支持沉浸材质时，应用自动降级但保持完整功能。

**优先级原因**：这是产品差异化视觉目标，但不得牺牲核心功能、兼容性或可读性。

**独立测试**：在支持和不支持官方沉浸材质的环境中分别启动应用、切换页签和主题，比较交互完整性与可读性。

**验收场景**：

1. **给定**设备支持参考工程使用的官方沉浸材质，**当**用户浏览主导航和底部页签，**那么**相关区域应启用官方材质效果及其适配行为。
2. **给定**设备不支持该能力，**当**用户打开相同页面，**那么**应用应使用稳定的背景与层级样式降级，导航和对话功能保持可用。
3. **给定**系统主题发生变化，**当**应用进入深色或浅色模式，**那么**文字、图标、输入区和状态提示应保持清晰辨识。
4. **给定**正在流式生成内容，**当**光感、页签或滚动状态变化，**那么**视觉效果不得中断消息接收或导致明显布局跳动。

### 边界情况

- JSON 文件过大、编码异常、重复配置、未知字段或 Key 为空时，应停止导入并提供可修正提示。
- 服务地址无效、证书异常、离线、超时、响应中断、限流或响应格式异常时，应保留已输入内容并允许恢复。
- 用户在流式输出期间切换会话、模型或删除当前配置时，应先阻止或结束当前请求，避免响应写入错误会话。
- 历史消息数量较多或单条回答很长时，应保持滚动、输入和会话切换可用。
- Key 不得出现在普通日志、错误提示、会话数据或完整界面回显中。
- 供应商存在能力或协议差异时，只能使用已验证的官方协议或用户明确配置的兼容协议，不得推断不存在的字段和功能。
- 推理标签跨流数据块被拆分、不完整或未闭合时，应保守保留可读内容，不得错误吞掉最终回答或伪造标签边界。

## 需求

### 功能需求

- **FR-001**：系统必须支持 OpenAI 兼容接口、OpenAI、Anthropic、Google Gemini、DeepSeek 与 GLM 六类供应商配置。
- **FR-002**：系统必须允许用户为每项配置提供可识别名称、供应商类型、必要服务信息、模型名和 Key。
- **FR-003**：系统必须支持应用内粘贴 Key，并以遮罩形式展示敏感字段。
- **FR-004**：系统必须支持通过系统文件选择流程导入包含供应商类型、必要服务信息、模型名和 Key 的 JSON 配置。
- **FR-005**：系统必须在导入前校验结构和字段，并向用户展示不暴露完整 Key 的确认摘要。
- **FR-006**：系统必须将 Key 保存在设备安全存储中，不得写入会话正文、普通偏好数据或普通日志；不得保留导入文件副本。
- **FR-007**：用户必须能够新增、查看摘要、编辑、启用、停用和删除供应商配置。
- **FR-008**：系统必须允许用户从有效配置中选择供应商和模型后创建文本会话。
- **FR-009**：系统必须将六类供应商归并为三种协议风格：OpenAI、OpenAI 兼容、DeepSeek 和 GLM 使用 OpenAI 风格；Anthropic 使用 Claude 风格；Google Gemini 使用 Gemini 风格。
- **FR-009A**：协议适配必须参考 HiveChat 的协议分层、消息映射、流式增量、结束状态、用量统计和错误处理行为，并针对 ArkTS 与 HarmonyOS 官方网络能力独立实现，不得直接复制 HiveChat 源码。
- **FR-009B**：所有供应商服务地址必须由用户填写；应用不得预置或猜测端点，只能根据用户选择的协议对输入地址进行格式校验和必要的、可预览的路径规范化。
- **FR-009C**：OpenAI 风格必须识别服务实际返回的正文增量、推理增量、结束原因和用量字段；Claude 风格必须识别消息开始、内容块增量和消息结束相关事件；Gemini 风格必须识别候选内容、文本分片、结束原因和用量信息。未识别字段必须安全忽略或报告协议异常，不得臆测含义。
- **FR-010**：系统必须支持连续上下文的流式文本回答，并明确显示生成中、已停止、完成和失败状态。
- **FR-011**：用户必须能够停止生成、重新生成最近回答和复制回答文本。
- **FR-012**：系统必须区分鉴权失败、限流、网络不可用、超时、服务异常与响应格式异常，并提供不泄露敏感信息的提示。
- **FR-013**：系统必须在设备本地保存会话列表、标题、配置与模型标识、消息顺序、正文、时间及生成状态。
- **FR-014**：用户必须能够新建、打开、继续、重命名和删除本地会话。
- **FR-015**：系统必须支持标题、段落、列表、引用和代码块的 Markdown 展示，并对不支持或不完整内容安全降级为文本。
- **FR-016**：系统必须适配系统深色和浅色主题，并保证导航、消息、输入区和状态信息可辨识。
- **FR-017**：系统必须严格采用参考工程中可验证的官方 UI Design Kit 沉浸光感能力，为主导航和底部页签提供官方材质效果，不得以自造 API 冒充沉浸光感。
- **FR-018**：系统必须在运行时检测官方沉浸材质可用性；不可用时采用普通背景、模糊或颜色层级的明确降级方案，且不得将降级效果宣称为官方沉浸光感。
- **FR-019**：系统必须支持手机和平板布局，首屏和核心操作不得因窗口尺寸变化而不可达。
- **FR-020**：系统必须在首次使用时说明 Key 由用户自行提供、请求将发送至用户选择的第三方供应商，并提示遵守相应服务条款与数据政策。
- **FR-021**：系统不得预置、生成或展示虚假的 Key、接口地址、模型能力、供应商响应或“已连接”状态。
- **FR-022**：系统必须仅在供应商响应实际包含独立推理字段或可完整识别的推理标签时，展示可折叠推理分区；最终回答与推理内容必须分离，且不得由应用生成推理内容。
- **FR-023**：系统必须记录 HiveChat 仅作为设计参考来源；实现产物不得直接包含其受附加许可约束的复制代码，避免形成未经许可的代码衍生移植。

### 关键实体

- **供应商配置**：名称、供应商类型、服务信息、默认模型、受保护的凭据引用、启用状态及最近校验状态。
- **模型选项**：用户明确配置或由已验证能力获得的模型标识，隶属于一项供应商配置。
- **会话**：标题、关联配置与模型、创建及更新时间和消息集合。
- **消息**：角色、正文、顺序、时间、生成状态和错误摘要。
- **导入预览**：尚未持久化的 JSON 解析结果，仅用于校验、遮罩展示和用户确认。
